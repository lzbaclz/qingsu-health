# 03 · 数据模型与事实状态

## 1. 表
| 表 | 作用 | 关键字段 |
|---|---|---|
| Patient | 假名患者 | display_code（P-0001）、clinic_id |
| Encounter | 一次就诊前采集或随访 | kind、status、protocol_id/version、parent_encounter_id、patient_confirmed_at、doctor_confirmed_at、followup_plan |
| Entry | **不可变原始记录** | seq、kind（body_map/free_text/answer/correction/doctor_note/system_notice）、payload |
| Fact | 事实（带版本） | key、status、value、evidence[]、source、version、superseded_by、patient_confirmed |
| AskedQuestion | 问过什么 | question_id、kind（protocol / clarification / verification）、fact_keys、answer_status |
| Summary | 摘要版本 | version、author（system / doctor:id）、content、note |
| Alert | 红旗触发 | rule_id、severity、patient_message、evidence、notice_entry_id、patient_disputed（患者核对时否认） |
| Task | 需要人处理的事项 | kind、status、assignee、history[] |
| Notification | 给患者的通知 | status（queued/sent/failed/seen/acknowledged）、history[] |
| VerificationReport | 验收结果 | passed、checks[] |
| AuditLog | 审计 | actor、action、target、detail |
| UsageEvent | 可用性测试埋点（不含输入内容） | type、payload（仅标量）、client_ts |

## 2. 事实的六种状态
| 状态 | 含义 | 摘要中怎么写 |
|---|---|---|
| present | 患者报告存在 / 给出了值 | 值 |
| denied | 患者**明确**否认 | "明确否认" |
| not_asked | 尚未询问 | "未询问"（关键事实列入缺口） |
| asked_unanswered | 问了但不清楚/跳过 | "已询问，未回答"（列入缺口） |
| uncertain | 模糊表达（好像/有点/可能） | "值（患者表达不确定）" |
| conflicting | 前后矛盾 | 两个候选并列，标红 |

**规则**：`not_asked`/`asked_unanswered` 永远不会因为"没提到"变成 `denied`；只有患者明确说"没有"或回答"否"才是 `denied`。

## 3. 证据格式
```json
{"entry_id": "ent_xxx", "quote": "前两天搬东西后左边腰酸", "kind": "free_text"}
```
- `kind`：free_text（逐字引用，验收 V3 校验）、body_map（"身体图标记：左腰"）、answer（"回答「…」：有"）、correction、doctor_note。
- 医生端任何事实都能展开证据并跳到对应 Entry。

## 4. 版本
- 事实：每次变化新建一行，旧行 `superseded_by` 指向新行；`version` 连续；同一 key 只有一行生效。
- 摘要：`version` 从 1 递增；v1 永远是系统版；医生编辑只允许 headline / narrative / doctor_notes，并写 `edit_log`。
- 医生修正事实：必须写依据（note）→ 新事实版本 + 新摘要版本 + 审计。

## 5. 随访的对比（change_card）
对协议 `followup.change_facts` 中的每个事实比较父/子就诊：
- `changed`：两次都明确但不同；`new`：上次未知、这次有；`unconfirmed`：这次未知；`unchanged`：相同。
- 附：本次触发的红旗、上次医嘱通知的送达状态、随访计划。

## 6. 协议中的表达式（when）
```
facts.<key>.present | .denied | .uncertain | .conflicting | .unknown | .answered | .value
facts.<key>.has('x') | .any([...]) | .gte(n) | .lte(n)
and / or / not / == / != / in / >= ...
```
白名单式求值器（不使用 eval），非法表达式在协议加载时报错。


## 7. 一键核对对事实的影响
| 患者选择 | 事实变化 | 证据 |
|---|---|---|
| 对 | 状态与值不变，新版本 | 追加「患者核对「…」：对」（kind=answer），从此不再算"只来自抽取" |
| 不对 | 回到 not_asked（值清空），协议题会重新直接问 | 新版本只含「患者核对…：不对」；被否定的抽取证据留在旧版本 |
| 不确定 | 记为 uncertain（值保留），协议题会再问 | 追加「患者核对…：不确定」 |
只核对关键事实（critical）与红旗类事实；身体图、直接回答、修改来的事实不核对。
