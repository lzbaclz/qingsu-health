## 本轮修复了什么

| 原有现象 | 已确认原因 | 修复与现在的行为 |
|---|---|---|
| 本机复述对照连续退回人工，只见ValueError | 输出schema允许患者引文缺省或为空；实测模型返回“一致”却无患者引文 | 引文改为非空必填，继续检查逐字出处和要点编号，错误保存为明确代码。20B四条合成复述均与开发标签一致，仍需医护核实 |
| 首诊恢复基线一直缺失 | 配置里已有两道基线题，但生成器没有合并 | 首诊与随访均采集近7天平均痛和活动影响，旧“现在痛几分”不被偷换为基线；未知不当零 |
| 一般病史可能被“这次出现”标题误导 | 首诊专用矩阵标题未合并 | 首诊使用逐行独立时间范围的标题，随访保留自己的问法 |
| 安全矩阵回答“没有”后，在新情况文本里报告危险症状仍无新提醒 | 文本追问只写入普通字段，没有进入症状抽取 | 明确的症状文本题通过 `extract_answer` 接入同一抽取/证据/红旗流程，并保留原问答来源。实际本机检查已触发预期紧急提醒及紧急核对，之前的否认仍在证据中 |
| 恢复图两张卡标题都变成“明显变差” | 后端合并字典时，判读label覆盖指标label | 指标名称与判读文案分开，图中明确标注近7天平均痛、活动影响；同日多次记录按顺序分开显示 |
| 原生日期控件的自动化填值未保存 | 原因尚未确认，不把它归因于已证实的产品缺陷 | 增加明确的今天/昨天选择和保存前日期预览，已在页面验证日期持久化与同条件差值；任意日期选择器仍未完成自动化验收 |
| 重新启动可能只看到旧演示快照 | 旧演示库会按设计保留创建时的协议 | `make demo`/`make backend`/`make seed` 使用本版独立的 `demo-v031-p026.db`，旧库不覆盖 |

## 已接入的六项创新能力

1. 病程事件记录主体、时间线索、报告时间与核实历史；新记录不被直接称为新发生。
2. 在相同协议下比较候选解释的处理路径，决定是否追加语义核实；安全必问保留。
3. 医生说明和患者复述按计划版本绑定，理解差异与执行障碍分开记录，人工核实独立留痕。
4. 患者确认自己的生活目标，按日期、单位和条件记录，条件不同或缺测不直接比较。
5. 候选协议在独立内存环境预演下一问、提醒和责任差异，不覆盖运行协议，不声称穷尽未来路径。
6. 24句/12对中文语境开发集与配对对照工具，保留来源、分母、失败、模型配置和代码/协议/数据哈希。

上述能力有工程与合成开发证据，不能据此称算法SOTA、全球首创或已证明临床价值。

## 实际验证与结果

- 最终完整后端 **218项通过**，前端构建与lint通过。原始记录见 `release_20260927/v031-tests.xml` 和 `verification_031.json`。
- 按当前协议另跑6条合成流程：改善、变差、基线缺测、随访缺测、零值、紧急终止，6/6符合预设工程检查。
- 既有开发集：完整流程33/40、问卷对照28/40无critical错误；20句压力集的粗心核对者18/20。旧随访标签与新版指标不同，另有词表误读和多余提醒，完整明细保留。不能只报通过数。
- 24句本机20B模型对照：目标字段符合标签从no_context的19/24，到all和action_sensitive均为23/24；后两者候选澄清数14与6。主体/时间标签为21/24，7/24句另有目标之外的断言待核验。数据参与过修复，非独立验证。
- 两遍症状抽取的中位耗时约77.09秒，p90约90.41秒；它不是隔离性能基准，也不支持“实时秒回”的宣传。
- 复述4条合成语句：4B模型修复结构后仍只有2/4标签一致；之后的20B配置为4/4。样本极小，不证明真实理解。所有失败和版本差异均保留。
- 最终0.2.6新症状文本入口还有一次真实本机调用。原检查脚本把“否认保留”过强地限定为必须形成同字段conflicting；模型实际只抽取小便专用字段，而先前大小便总问答仍为denied且保留原话。原始false报告保留，另附基于原始证据的检查口径说明，没有重跑模型或改写输出。

24句原生运行冻结于0.2.5协议。之后0.2.6新增了文本题接入。已经核对共享抽取提示、事实定义、事件规则、任务路由与核心源码完全相同；新增入口和显示修复另行验收，不把旧运行冒充新推理。该原生运行的63个源码/数据/协议文件按当时SHA256逐一核对并归档。
