# 清诉 Qingsu Health

帮肌骨康复门诊把患者**两次就诊之间的变化**核实清楚。患者用自己的话说，系统按写好的问诊规则追问并保留原话，最后交给医护逐条核对。

> **当前状态：工程原型（应用 0.3.1，2026-09-27）。** 只在模拟数据上验证过。问诊规则目前是 AI 起草的草案，还没有经过医生审核，不能用于真实患者。

名字念作 qīng sù，和"倾诉"同音：把患者的倾诉，整理成医护能核对的清楚记录。项目原名「体迹 AI」，界面、BP 和代码里的配置名（如 `TIJI_*`、`tiji.db`）暂时还是旧名。

德邻杯 2026 AI 创业大赛参赛项目，首个模拟场景是成人腰背痛。

## 它解决什么问题

康复治疗通常要来好几次门诊。两次就诊之间，患者会有变化：哪里更疼了，新出现了什么，医生交代的练习做没做到。这些信息现在常常：

- **说不清**：分不清说的是自己还是家人，是刚开始还是老毛病。
- **记不全**：没问到的事，容易被当成"没有"。
- **没人接**：消息发出去不等于患者看到，看到不等于理解，理解不等于做到。

## 怎么用

**患者（手机）**

1. 用门诊发的一次性邀请链接进入，先逐条确认适用范围（如年满 18 岁、没有怀孕），有一条不符合就不进入填写。
2. 在人体图上点出不舒服的位置，用自己的话说近况。
3. 系统按问诊规则补问，安全相关的问题一定会问。出现危险信号时，页面立即提示打电话给门诊或 120，不等后台有人上线。
4. 说法含糊、又会影响处理的地方单独核实：说的是谁（本人还是别人），什么时候开始，是新出现、一直有、加重还是减轻。
5. 患者看一遍系统整理的内容，确认或改正。
6. 医生发布计划后，患者用自己的话复述要点，并单独说明做不做得到、难在哪里。
7. 患者可以定下生活上的目标（如能坐多久、能走多远），之后按日期追加记录。条件不同或漏测的记录不拿来比较。

**医护（电脑，需登录）**

- 只看得到本机构的记录。医生、护士等角色权限不同，操作人以登录账号为准。
- 整理出的每一条信息都能点回患者原话。
- 联系不上患者时要留下尝试记录。任务不能直接结案，会升级并保持打开。
- 修改问诊规则前可以先"预演"：同样的情况下，新版本会问什么、提醒谁。预演不影响正在使用的版本。

## 它不做什么

- **不诊断、不开药、不给个人训练方案。**
- **AI 不决定流程。** 问什么、什么时候提醒、提醒谁，都写在问诊规则（`protocols/` 里的协议文件）里，由程序照规则执行。规则本应由医生制定，现在的版本还是 AI 起草、待审核的草案。AI 只做三件事：从患者的话里抽取信息（必须附原话出处），把整理好的信息写成简短叙述，比较患者复述和计划原文。
- **不替人下结论。** 患者确认的是"我是这么说的"，医护核对的是"整理得对不对"。系统不会自动认定疗效、理解或执行情况。附上原话出处只能说明信息有来源，不能说明理解正确。
- **不改旧记录的规则。** 每条记录固定使用创建时的协议版本，协议更新后旧记录不会自动换用新规则。

## 快速开始

需要 [uv](https://docs.astral.sh/uv/)、[pnpm](https://pnpm.io/)、Python 3.11+、Node 20.19+ 或 22.12+。

```bash
make setup      # 安装后端与前端依赖
make demo       # 启动后端 http://127.0.0.1:8000，用独立的演示数据库，不会清空已有数据
make frontend   # 另开一个终端，然后打开 http://localhost:5173
```

- 医护账号是 `demo-doctor`，随机口令在 `backend/.local/demo-v031-access.txt`（只有本人可读，不进 git）。
- 登录医护端后生成一次性患者邀请，再用邀请链接打开患者端。
- `make demo` 固定使用离线词表（`mock`），不需要任何模型 key，界面上会标明。

| `make access-account` | 手工创建机构账号（生成的口令文件不要提交） |

### 接真实模型

在 `backend/.env` 里设置 `TIJI_LLM_PROVIDER`，各项写法见 `backend/.env.example`：

| 取值 | 说明 |
|---|---|
| `mock` | 离线词表，默认值，结果可复现 |
| `ollama` | 本机模型，患者原话不离开这台电脑 |
| `compat` | DeepSeek、通义千问、智谱等 OpenAI 兼容接口 |
| `anthropic` | Claude，需要 `ANTHROPIC_API_KEY` |

演示时换模型，在 `backend/` 目录运行 `.venv/bin/python -m app.demo --provider ollama --database .local/demo-v031.db --access-file .local/demo-v031-access.txt`，模型名等其余设置仍从 `backend/.env` 读取。

真实模型出错时会退回离线词表，并在界面上标出；评测时关掉退回，以免混淆结果。目前真实模型只处理过合成文本。**未经数据处理授权，不要把真实患者信息发给任何外部模型服务。**

## 数据与安全

- 正式模式（`TIJI_MODE=production`，也是默认值）隐藏 API 文档和演示接口，并拒绝使用草案协议。
- 数据库和导出文件默认不加密。正式部署还需要 HTTPS、磁盘与备份加密、真实机构账号和临床批准。
- 备份、恢复、按患者导出和受控删除的用法见 [docs/23](docs/23_数据维护与部署检查.md)。删除只覆盖当前数据库，不包括历史备份和已导出的副本。
- 外部消息通道默认没有配置。"已发送""已看到""已确认"分开记录，都不等于理解或做到。
- 这些工程措施不代表已经取得资质或授权，监管分类需要由有资质的机构评估，见 [docs/06](docs/06_合规与责任边界.md)。
