# 真实人模拟交互测试 · 任务卡与记录表

## 本轮安排（模拟评审 P0-5）：先做 10 人，另外 10 人与盲评挪到决赛前
- 10 名非团队成员，每人 2 张卡，共 20 次。卡的分配（顺序随机平衡）：P01–P05 做 A→C，P06–P10 做 C→B；卡 D（随访）留到决赛前那一轮。
- 每位参与者约 20 分钟，建议集中两个半天完成（9/25 下午、9/26 上午）。
- 主持人（工程）负责操作与记录；医生审核 4 张卡的情境描述（约 20 分钟，9/25 前）。

## 植入错抽（第二轮评审新增，必须做）
评测里的"走完核对后关键错误 0"是知道标准答案的模拟患者点出来的，等于用答案核对答案。真实的人会不会一路点"对"，只有这轮测试能回答。
- 用 `make user-test-backend` 启动后端（它打开 `TIJI_USER_TEST_PLANT=1`）。**演示和录视频时不要用这个命令。**
- 卡 A 和卡 B 各会被系统故意放错一条信息，引文取自参与者自己的原话。两条故意做成两种难度（第三轮评审 §2.1 Q4）：
  - 卡 A · 显眼型：显示"疼痛串到臀部或腿：有"，引文多半是"腿没有麻"——错误值旁边就是反驳它的原话，测的是**上限**；
  - 卡 B · 隐蔽型：显示"这次不舒服开始多久：超过 3 个月"，引文取"去年也闪过一次腰"——引文看起来支持错误值，
    和真实错抽"腰疼老毛病了 → 超过 3 个月"同型，更接近真实情况。参与者没提去年那次时，系统退回用"一个多月"那句做引文，记为显眼型。
- 汇总分两种类型报"点不对"的比例，并带 95% 区间。每种只有约 5 例，区间会很宽，只能说明"有没有明显问题"。
- 主持人**不提示、不追问**，让参与者照常核对。系统自动记录他点了"对 / 不对 / 不确定"，以及确认页有没有改掉。
- 这张卡做完、复述问题问完之后，再当场说明："刚才核对里有一条是我们故意放错的，用来测试核对这一步有没有用。"并问一句"你当时注意到了吗？为什么？"，答案写进 notes。
- 分配不变：P01–P05 做 A→C，P06–P10 做 C→B，所以 10 个人每人正好遇到一次植入。汇总表会报"植入错抽被点'不对' X / 10"，没点"不对"的每一例都要在备注里写原因。

## 主持人操作（照做即可，数据自动记录）
1. 启动：`make user-test-backend`、`make frontend`（不需要清库；测试记录靠编号区分）。
2. 每张卡用一个编号：`UT-<参与者>-<卡>`，例如 P03 做卡 C 就是 `UT-P03-C`。
3. 给参与者的手机或电脑打开：`http://<电脑IP>:5173/p?code=UT-P03-C`（编号自动带入）。
   - 卡 D（随访）要先准备"上次就诊"：`curl -s -X POST localhost:8000/api/dev/followup-parent -H 'Content-Type: application/json' -d '{"patient_code":"UT-P03-D"}'`，返回的 `start_url` 前面加 `http://<电脑IP>:5173` 即可。
4. 参与者完成后，主持人当场问一句"现在下一步该做什么？"，并把结果写进 `eval/user_test/主持人记录.csv`（复制模板 `主持人记录_模板.csv` 改名）：
   `code, retell_ok(1/0), burden(1–5), saw_notice(1/0，仅卡 C), understood_notice(1/0，仅卡 C), notes`
5. 全部结束后：`make user-test-report` → 生成 `eval/user_test/汇总_<时间>.md/.json`；`python eval/evidence_table.py` 会把结果放进 BP 证据表。
6. 页面上的每一步（身体图、描述、每道题、一键核对、确认页修改、紧急页按钮）都会自动记录耗时，不记录输入内容。

## 为什么是这些指标
完成率、用时中位数、复述下一步、卡 C 是否看到并理解紧急提示、植入错抽被点"不对"的比例——对应 docs/05 §6 与 Nature Medicine 2026 那项研究的教训："模型答对"不等于"人做对"。


目的：检验普通人能否用自己的话把情境说清楚、是否理解每一步、是否知道下一步该做什么。
**不是**让参与者提交自己的真实病情；**不是**评价任何医学判断。参与者 20 人（非团队成员），每人 2 张不同任务卡，顺序随机平衡（A→B / B→A 各半）。

## 给参与者的说明（口头 + 书面）
- 这是一个原型测试，测的是软件，不是你。
- 请把卡片当作你自己的情况，**用自己的话**说，不要照读；卡片没写的，按你觉得合理的方式回答或选"不清楚"。
- 全程不会收集你的姓名、手机号或真实健康信息；记录只用于改进产品。
- 你打的字只在这台电脑上处理（默认离线模式）。如果主持人改用了模型服务，会先告诉你是哪家、数据在哪里处理，你同意后再开始。
- 随时可以停止。

## 任务卡（4 张；每张只给情境，不给医学词）
**卡 A · 搬东西之后**
你三天前帮朋友搬家，第二天开始腰的左边一直酸酸的，坐久了更难受，躺一会儿会好一点。腿没有麻，也没有别的不舒服。你想在见医生前先把情况说清楚。

**卡 B · 说不清左右**
你腰不舒服一个多月了。去年也闪过一次腰，那次休息几天就好了。这次一开始是左边，这几天觉得右边更明显，走路久了右腿有点发麻。你不太确定到底哪边更严重。

**卡 C · 有点吓人的情况**
你腰痛差不多三个月，最近越来越痛，左腿发麻。这两天你发现小便有点憋不住。你有点担心，但不知道要不要马上去医院。

（卡 A、卡 B 做测试时，系统会各放错一条信息，见上面"植入错抽"。给参与者的卡片上不写这件事。）

**卡 D · 复查**
一周前你看过医生，医生让你一周后在这里更新情况。这一周你更疼了，疼痛串到右边屁股，右腿开始发麻。医生上次说的注意事项你记不太清了。

（卡 D 需要主持人先用演示账号 P-0004 的已确认就诊作为"上次就诊"。）

## 主持人流程（每人约 25 分钟）
1. 说明（2 分钟）→ 2. 卡 1 任务（8 分钟）→ 3. 复述："现在下一步是什么？"（记录）→ 4. 卡 2 任务（8 分钟）→ 5. 复述 → 6. 三个开放问题（5 分钟）：哪一步最不明白？有没有觉得系统"猜"了你没说的话？确认页你改了什么？

## 汇总指标（对应 docs/05 §6）
- 完成率 = 完成的卡 / 全部卡（目标 ≥80%）
- 用时中位数（目标 ≤4 分钟）
- 下一步复述正确率（目标 ≥90%）
- 卡 C 中看到并正确理解紧急提示的比例（必须报告）
- 误解与返回修改的分布，按卡分组
**20 人做两张卡仍是 20 名参与者，不是 40。**
