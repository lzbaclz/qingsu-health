# 数据维护与部署检查（0.3.1）

本工具供有文件权限的本机管理员使用。它不能替代机构的数据保留、医疗记录、授权和供应商义务。所有验证只在合成数据库的副本上执行。

## 备份与恢复

从 backend 目录使用自己的实际路径，目标必须为新文件：

```bash
.venv/bin/python -m app.data_admin backup --database /绝对路径/source.db --output /绝对路径/new-backup.db
.venv/bin/python -m app.data_admin restore --database /绝对路径/new-backup.db --output /绝对路径/restored.db
```

通过 SQLite backup 接口取得一致性副本，执行 integrity_check，返回 SHA256。新文件权限为 0600，拒绝覆盖已有文件。恢复到新路径，默认撤销会话、删除邀请并将未送达外部投递设为未配置，防止旧凭据复活和未经核对重发。切换服务、账号访问和真实消息配置仍由机构管理员操作。不要将恢复副本与原库同时接入真实发送通道。

文件未自动加密；正式环境需要磁盘/备份加密、密钥隔离、访问控制和恢复演练。保存周期按机构实际政策，不能从演示阈值推断。

## 患者导出

```bash
.venv/bin/python -m app.data_admin export-patient --database /绝对路径/source.db --clinic 机构ID --patient 患者ID --output /绝对路径/new-export.json
```

导出该机构/患者的就诊、原话、事实版本、事件、计划、回复、观察和相关审计。排除会话与邀请令牌摘要。只写新文件、权限 0600。导出含健康信息，分享前须按实际授权处理；不会自动发送给外部。

## 保存期清单与删除

```bash
.venv/bin/python -m app.data_admin inventory --database /绝对路径/source.db --clinic 机构ID --older-than-days 365
.venv/bin/python -m app.data_admin delete-patient --database /绝对路径/source.db --clinic 机构ID --patient 患者ID
```

365 只是示例检查阈值，**不是法定保存期**。inventory 仅列待审查对象，不会自动删记录。delete-patient 默认返回各表行数；实际删除需机构明确处置依据、停服务并核对未结事项后，追加 `--execute --confirm-patient 同一患者ID --policy-reference 机构批准记录引用`。程序拒绝删除发送中的任务，事务内删除关联记录并留不含患者内容的处置记录。引用是操作记录，软件无法验证其法律有效性。

删除仅覆盖当前数据库。历史备份、既有导出、外部消息和机构其他系统副本要按同一处置政策人工处理。工具不声称安全擦除磁盘残留。没有对用户的原数据库执行删除。

## 运行配置与最小暴露

`TIJI_MODE=production` 时隐藏 API 文档和演示端点；草案或模拟协议无法创建患者采集。HTTPS、同源 CORS、真实机构账号、随机口令和实际临床批准均需配置。`/api/health` 只返回存活；`/api/status` 和模型 probe 要医护授权。公共协议与身体图用于患者开始页，不含患者记录。

外部投递默认未配置。配置 `TIJI_DELIVERY_CONFIG` 后仍需机构核对接收方、密钥与数据条款；HMAC、幂等与最多三次失败不保证接收方已处理。不在当前演示中接入真实消息。

## 已做的验证

自动检查覆盖：新文件保护、备份完整性、文件权限、机构归属拒绝、导出不含令牌、删除预览与错误对象拒绝、删除只影响指定患者、源数据库保持原样、恢复凭据撤销。它没有模拟磁盘故障、全量生产负载或不同版本数据库迁移。
