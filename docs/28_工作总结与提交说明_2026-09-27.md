## 已实现的产品与工程能力

| 能力 | 解决的需求与使用方式 |
|---|---|
| 病程事件核实 | 分开记录本人／他人、过去／现在、首次记录／新发生；患者纠正和医护核对保留历史 |
| 根据处理差异追问 | 在相同协议下比较候选解释会触发的处理路径，追加必要的语义核实；固定安全必问继续执行 |
| 计划复述与执行障碍 | 医生发布带版本的说明和要点，患者复述并说明执行困难；模型对照与医护核实分别记录 |
| 生活目标与恢复记录 | 患者确认目标、日期、单位和条件；同条件记录才比较，缺测不记作零 |
| 协议修改预演 | 医护可在独立内存环境查看候选协议带来的下一问、提醒和责任变化，不改写正在运行的记录 |
| 中文语境评测 | 建立 24 句／12 对开发样本与配对对照工具，保存失败、分母、模型配置和源码／协议／数据哈希 |

同时补齐了医护登录、机构与角色权限、一次性患者邀请、会话失效、服务端审计身份、不可变协议快照、任务升级、后台调度和通知队列。联系失败会留下记录、升级并保持待处理；消息发出不自动算作患者看到或任务完成。

数据维护工具支持限定范围的导出、备份、恢复和受控删除。删除默认先预览，恢复后旧会话失效。默认演示使用独立数据库和随机口令，保留原有数据库。

## 已确认的问题与修复

| 原有现象 | 已确认原因 | 修复后的行为 |
|---|---|---|
| 复述对照返回“一致”，却缺少患者原话 | 输出结构允许缺省或空引文 | 引文非空必填，并核对逐字来源与要点编号；无有效证据转人工核实 |
| 首诊恢复基线一直缺失 | 协议生成器未合并已配置的两道基线题 | 首诊采集近 7 天平均痛和活动影响；缺失仍标为未知 |
| 首诊病史的时间范围容易误读 | 首诊专用安全矩阵标题未合并 | 首诊使用逐行独立时间范围的标题，随访保留相应问法 |
| 安全题回答“没有”后，新文本中的危险症状未触发提醒 | 文本题答案只写入普通字段，未经过症状抽取 | 明确的新症状文本题接入抽取、证据和提醒流程；保留原否认与原问答来源，紧急时停止常规问询 |
| 恢复图的指标标题被判读文字覆盖 | 字典合并时两个用途共用 `label` | 指标名称与判读分开，图中使用正确标题；同日记录按顺序显示 |
| 问卷对照评测仍可能调用文本抽取 | 对照分支只关闭了初始自由文本抽取 | 评测器同时关闭初始自由文本和文本题答案抽取，最终报告重新生成 |
| 演示启动后仍显示旧协议 | 历史记录按设计保留旧快照 | 本版演示命令使用独立的 `demo-v031-p026.db`，原数据库保持原样 |

另外增加了“今天／昨天”日期按钮和保存前预览，已验证日期持久化与同条件差值。原生日期控件的自动化填值曾失败，原因尚未确认；不能把它写成已确认并彻底修复的产品缺陷，任意日期选择仍未完整验收。
