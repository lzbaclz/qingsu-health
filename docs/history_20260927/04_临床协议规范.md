# 04 · 临床协议规范（医生与工程的正式接口）

协议文件：`protocols/<protocol_id>.yaml`，示范：`protocols/lbp_adult_v0.1.yaml`。
**医生决定内容，工程保证每一条可执行、可验证、可版本管理。** 改完运行 `make protocol-check`（或 POST `/api/protocols/validate`）即可知道格式是否合法。

## 0. 头部
```yaml
protocol_id: lbp_adult_v0.1      # 文件名同名
version: "0.1.0"                 # 每次临床改动递增
status: draft                    # draft → clinically_reviewed → approved（approved 前不得用于真实用户）
owners: {clinical_lead: …, clinical_reviewer: …, engineering: …}
review: {last_reviewed: 2026-09-xx, next_review: …, sources: [参考的指南/教材/科室流程]}
```

## 1. scope —— 适用范围（医生交付物 #1）
| 字段 | 医生要写什么 |
|---|---|
| inclusion / exclusion | 谁能用、谁不能用（年龄、孕期、外伤、代填……） |
| setting / service_hours | 什么门诊、什么时间有人看 |
| service_notice | 进入前给患者看的用途与边界说明 |
| emergency_notice | 全程可见的紧急提示（哪些情况不要等线上回复） |
| out_of_scope_message | 不适用时告诉患者什么 |
| contact_label / contact_phone | 紧急终止页"打电话给门诊"主按钮（为空则只显示急救电话） |
| emergency_phone | 急救电话，默认 120 |

## 2. facts —— 事实清单（医生交付物 #3：事实表达规范）
每条事实是"我们希望摘要里明确其状态的一件事"。
```yaml
- key: leg_numbness               # 英文下划线，全协议唯一
  label: 腿或脚是否发麻            # 患者与医生看到的名字
  type: bool                       # bool | enum | multi_enum | number | scale | text | body_regions
  category: associated             # 分组：location/onset/character/severity/…/red_flag/followup
  required: true                   # 摘要必须明确其状态（含"未知"→列入缺口）
  critical: true                   # 评测关键事实：遗漏/编造算严重错误
  options: [{value: left, label: 左侧, synonyms: [左边, 左侧]}]   # enum/multi_enum 必填
  lexicon:                         # 离线抽取与测试用词表（临床可补充口语/方言）
    present_terms: [腿麻, 脚麻, 发麻]
    denied_terms: [不麻, 没有麻]
    context_terms: [痛, 疼]        # 可选：只在含这些词的句子里抽取
  min: 0 / max: 10                 # number/scale
  notes: 给工程/临床的备注
  clinical_review_required: true   # 审核后改为 false
```
医生需要决定的：哪些事实、每个事实的可选值、什么表达算"有/没有/不确定"、哪些是关键事实。

## 3. questions —— 问询流程（医生交付物 #2）
```yaml
- id: q_leg_weakness
  fact_key: leg_weakness
  type: yes_no                     # yes_no | single_choice | multi_choice | scale | number | text | body_regions
  priority: 12                     # 小的先问
  when: facts.leg_weakness.unknown # 触发条件（可省略）；见 docs/03 §6 表达式
  text: 腿有没有觉得没劲、软、抬不起来？
  allow_unknown: true / allow_skip: true
  purpose: 为什么问（给复核者看）
  stage: pre_visit | follow_up | both
  tier: 1                          # 1 = 必问（范围核查/红旗），不计入 max_questions；默认 2
```
引擎规则：只问状态仍为未知的事实；已明确不问；问过一次不再问；矛盾先澄清；`max_questions` 到达即停。
医生需要决定的：问题顺序（红旗先问）、措辞、条件、上限。

## 4. clarifications —— 矛盾澄清模板
同一事实出现两种说法时怎么问。占位符：`{label} {first} {second} {first_source} {second_source}`。
`resolve` 取值：`keep_first | keep_second | both | changed_to_second | unknown`。没有模板的事实用通用模板。

## 5. red_flags —— 需要人工处理的情况（医生交付物 #4）
```yaml
- id: rf_bladder_bowel
  label: 大小便控制变化
  when: facts.bladder_bowel_change.present
  severity: urgent                 # urgent | same_day | routine
  action: immediate_notice_and_task   # 或 task_only（只给医生，不提示患者）
  on_trigger: stop_questioning     # 紧急级建议终止问询：已经让患者去急诊，就不要再让他答题；其它级别用 continue
  patient_message: >-              # 经审核、可直接给患者看的文字
    你提到…请立即联系门诊或前往急诊。
```
医生需要决定的：条件、级别、谁负责（在门诊流程里）、给患者的原话。
**工程保证**：触发即向患者展示提示（不等待线上回复）+ 生成任务；任务完成必须有人。

## 5.5 verification —— 一键核对
```yaml
verification:
  enabled: true
  include_critical: true           # 关键事实
  include_categories: [red_flag]   # 以及这些类别
  max_items: 8
```
只从自由文本抽取、未经患者直接回答的上述事实，会在继续问询前请患者逐条确认（对 / 不对 / 不确定）。

## 6. scope_guard —— 越界检查
正则列表；系统生成的、面向患者/医生的文字命中即验收失败。医生可补充本专科常见的病名、药名。

## 7. education —— 宣教内容
只放流程性说明；任何涉及诊疗建议的内容都不进首版。

## 8. followup —— 随访
`default_interval_days`、`change_facts`（变化卡对比哪些事实）、`questions`（随访问题，stage: follow_up）。

## 9. summary / evaluation —— 摘要顺序与评价标准（医生交付物 #6）
- `summary.key_facts_order`：医生希望先看到什么。
- `evaluation.critical_facts`：评测的关键事实。
- `evaluation.error_taxonomy`：错误分类（E1–E9）与严重度，评测报告按此统计。

## 10. 修改流程
1. 医生在 `protocols/templates/医生工作表.md` 里先用表格写，工程转成 YAML；或医生直接改 YAML。
2. `make protocol-check` 校验；错误信息会指出行/字段。
3. 每次临床改动：`version` 递增、`review.last_reviewed` 更新、相应条目 `clinical_review_required: false`。
4. 全部条目审核完、第二位临床复核者签字 → `status: approved`。
5. 协议改动后重跑 `make eval`，锁定集结果变化要记录在 `eval/results/`。
6. v0.1 → v0.2：医生在 `protocols/review/decisions.yaml` 里逐条选 adopt / modify / drop，`make protocol-v02` 生成 `protocols/lbp_adult_v0.2.yaml` 与审核报告；议程见 `protocols/review/医生审核会_90分钟议程.md`。
