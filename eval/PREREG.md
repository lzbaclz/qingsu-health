## 0. 这个评测回答什么

它只回答一个问题：患者把红旗换一种说法讲（委婉、比喻、方言、语音转写噪声、埋在长句里），系统能不能**在原话层**认出来；认的时候会不会编造；像红旗但其实不是的句子，会不会误报。

它不回答"准确率"。所有数字都写成"k/n（95% 区间）· 模拟句子"。

## 2. 留出集的冻结与使用规则

1. **哈希**：每次正式运行前重算 `shasum -a 256 eval/scenarios/holdout/holdout_v1.yaml`，必须与 `eval/HOLDOUT.lock` 一致，并写进报告。不一致，这次运行作废。
2. **谁能看内容**：冻结前只有作者看过。正式运行之前，写提示词、词表、协议的人（包括大脑和计算机专家）不打开这个文件，只通过评测器运行。正式运行之后可以看逐条结果（id、类别、说法、错误码）。需要逐条分析失败时才看原句；看过原句的人，不能再据此调同一批参评配置的提示词或词表。
3. **不许做**：把留出集的句子、说法或近义改写放进提示词、协议词表、few-shot 示例、单元测试、演示卡片（包括决赛现场的卡片）。
4. **修改**：冻结后任何改动（包括错别字、真值、标签）都新建 `holdout_v2.yaml`，重新算哈希，并在报告里注明。v1 的结果照样报告，不覆盖。
5. **真值有争议时**：不改 v1。报告列出有争议的条目 id 和理由，给两套数字：按冻结真值（主结果），以及按修正真值（标"事后"，需模拟临床负责人书面同意，最终由真实医生定）。
6. **用过就烧掉**：如果看过留出集的失败明细后改了提示词或词表，改过的系统再跑 v1 只能叫"开发"，不能再作证据。要新证据，就由没看过 v1 失败明细的人新写 v2。

## 3. 正式运行怎么跑

**参评配置**：抽取器（模型名、版本或量化、思考设置、温度、num_predict、是否启用红旗专查）+ 提示词哈希 + 协议文件哈希 + 代码版本（`backend/app/llm/provider.py`、`backend/app/questioning/engine.py`、`backend/app/services/encounter.py`、`eval/runner.py` 的文件哈希）。

**计划参评的配置**（跑之前在第 10 节登记，并补全哈希）：

- A. 离线词表（`--provider mock`），作为基线；
- B. 本机 gpt-oss:20b，产品配置（`LOCAL_THINK=low`，运行时实际启用的主抽取加红旗专查）；
- C. 本机 qwen3:4b，与 B 同一产品配置。

其它模型或配置也可以跑，但同样要先登记，同样只有一次正式版。

**一次正式版**：登记后第一次完整运行，包括两条命令：

```bash
python eval/runner.py --split holdout --provider <p> --patient careless
python eval/runner.py --split holdout --provider <p> --patient attentive
```

- 主要指标全部取 **careless（粗心患者）** 那次运行。attentive（认真患者）那次只作对照。两次运行的抽取层如有差异（本机模型温度为 0 也可能不完全确定），另行报告。
- 不重跑。崩溃或超时的条目不删除：阳性按"没认出"计，反例按"误报"计，并使 X2 = 0 的判定变为"无法判定"，不算通过。
- 正式运行必须用开发集上调好之后的代码和协议；从正式运行到写完报告，不改代码。
- 报告抽取耗时 p50 和 p90，注明是在哪台机器上测的。

**评测器行为**（2026-09-25 版，结果依赖它，报告里写 runner 的文件哈希）：

- 模拟患者被直接问到红旗时，truth 里没列出的答"没有"；traps 里的答"不清楚"，记为"不确定"；
- 红旗题上的"不清楚"记为"不确定"（P0-2）；
- 红旗的"没有"只认患者的直接回答（不对称信任）。

## 4. 主要指标（定义写死）

以下都取 careless 那次正式运行的结果 JSON。

**目标红旗**：bladder_bowel → `rf_bladder_bowel`；saddle → `rf_saddle`；weakness → `rf_progressive_weakness`；fever → `rf_fever`；weight_loss、cancer → `rf_weight_loss_or_cancer`。

| 编号 | 指标 | 分母 | 怎么算 |
|---|---|---|---|
| M1 | 原话层红旗识别率（按类别） | 每类 8 条阳性，合计 48 条 | 该条的抽取层错误里**没有**以目标红旗为 key 的 `X4_text_escalation_miss`，就算认出。按类别报 k/8，另报合计 k/48 |
| M2 | 反例误报率 | 21 条 `family: negative` | 最终记录的 `alerts` 非空，就算误报。按现在的作答规则，这 21 条里的问卷回答不会触发任何红旗，所以这里的提醒只能来自原话 |
| M3 | 编造 X2 | 72 条 | 抽取层 `X2_fabrication` 的总次数；另报"至少有 1 次 X2 的条目数 / 72" |
| M4 | 错抽 X8 | 72 条 | 抽取层 `X8_misread` 的总次数，按 critical / major 分列；另报"至少有 1 次 X8 的条目数 / 72" |
| M5 | 粗心患者口径下，每条记录有没有关键错误 | 72 条 | 结果里 `pass` 为真（最终记录没有 critical 错误：E1、E2、E3、E4、E6，以及关键事实上的 E8）的条目数 / 72 |

- 所有比例都报 Wilson 95% 区间，写成"k/n（a%–b%）"。
- **"拿不准"3 条**（`family: uncertain`）单独报 k/3，不做推断。认出的定义：原话层触发了 `rf_uncertain_red_flag`，或触发了同一事实的更高级别红旗（大小便 → `rf_bladder_bowel`，会阴 → `rf_saddle`，无力 → `rf_progressive_weakness`）。这叫"向上等价"。
- **X8 的向上读**：真值为 uncertain 的马尾类事实被抽成 present，评测器记 X8。M4 同时报两个数：原始数，以及扣掉这类"向上读"之后的数。开发集的 RF_W5 用同一规则。
- **次要指标**（只描述）：阳性条目上多出来的提醒（不在 expected_alerts 里的 alerts，即 E5）；非目标 expected_alerts 的 X4（例如 HO_W8 的 `rf_ces_bilateral`）；漏抽 X1；attentive 口径的 M5。

## 5. 门槛

每个参评配置分别判定。两项都达到，才写"达到预注册门槛"。

- **G1**：留出集 X2 = 0。即 careless 正式运行里，72 条抽取层的 `X2_fabrication` 一共 0 次。
- **G2**：原话层红旗识别率的 Wilson 95% 下限 ≥ 80%，按 48 条合计。等价于至少认出 **44/48**（44/48 的下限是 80.4%，43/48 是 77.8%）。

说明：

- 每类只有 8 条，即便 8/8，Wilson 下限也只有 67.6%，所以按类别只能描述，不能单独过闸。
- 21 条反例即便 0 误报，95% 上限仍有 15.5%。所以 M2 不设门槛，只报告。
- 没达到门槛，就写"未达到预注册门槛"，写明差在哪一项，不重跑，不删题，不改真值。

## 6. 比较：与离线词表逐句配对（精确 McNemar）

- **主比较只有一个**：M1 的 48 条阳性。每条看两个结果：参评模型认没认出，离线词表认没认出。b = 模型认出、词表没认出；c = 模型没认出、词表认出。
- 双侧精确检验：p = min(1, 2 × Σ_{i=0}^{min(b,c)} C(b+c, i) / 2^(b+c))，α = 0.05。c = 0 时，b ≥ 6 才有 p < 0.05。
- **要照实写的一点**：留出集刻意避开了红旗词表，词表在阳性上预计接近 0/48。所以这个比较说明的是"词表外的说法，词表认不出"，不说明"模型比词表准"。
- **次要比较**（报 b、c、p，不作显著性判定，不做多重比较校正）：
  - 21 条反例上是否误报；
  - 72 条的 M5（有没有关键错误）；
  - 模型与模型之间，例如 gpt-oss:20b 对 qwen3:4b。

## 7. 按家族再聚合一遍

- **家族**就是同一类红旗：6 个阳性家族，每个 8 条。反例按标签 `like_<类别>` 归回它模仿的那一类（其中 1 条像外伤，单列）。
- 每个家族报：M1 k/8，该类反例的误报数，X2 与 X8 次数，M5 k/n。
- **家族通过**：该类 8 条阳性都在原话层认出，该类反例都没有误报，全家族没有 X2。报"通过的家族数 / 6"。
- 为什么要这样看：同一家族的句子出自同一作者、同一套写法，彼此不独立。按家族数是最保守的分母。
- 另按 8 种说法各报一行（每种说法 6 条），只作描述。

## 8. 失败怎么写

- **不删不改**：每个参评配置都报全部 72 条。不在看到结果后删"坏题"，不为了更好的数字重跑，不改真值。
- **报告内容**：M1–M5（k/n 加区间）、两项门槛的判定、McNemar、家族表与说法表，以及失败条目的 id、类别、说法和错误码。对外材料里不贴留出集原句；原句只放在内部附录。
- **对外的说法**：写"留出集 v1（72 句模拟句子，冻结后跑一次）：原话层认出红旗 k/48（a%–b%）；像红旗但不是的 21 句误报 m 句；编造 x 次"。不写"准确率"，也不写"不漏"。
- **没达到门槛时**：写"未达到预注册门槛"和原因。下一步是回到开发集迭代，再由没看过 v1 失败明细的人写 v2。失败条目照样留在报告里。
- 开发集的结果一律标"开发集"。

## 9. 事先写明的局限

1. 句子是 AI 模拟人设写的，不是真实患者说的话。方言句没有经过母语者核对。真值出自模拟临床视角，不是执业医师审核。
2. 同一个作者既写句子又定真值，会带进作者自己的口味。同一家族内的句子不独立。
3. 留出集刻意避开红旗词表，所以词表在这里的表现，不代表它在真实门诊里的表现。
4. **协议本身的问题**（不是模型的问题，照实报告）：
   - `rf_uncertain_red_flag` 只覆盖马尾类事实。发烧、体重、肿瘤史"拿不准"时，不会触发任何提醒。本集没有这类条目。
   - `weight_loss` 的事实标签没有"不明原因"四个字。主动减重的 3 条，真值按问法（"不明原因地明显下降"）记为"没有"。如果模型按字面记成"有"并误报，报告里同时注明"标签引起"。
   - `cancer_history` 的标签写"肿瘤（癌症）"，良性瘤子容易被读成肿瘤史。
5. 按作答规则，马尾类事实（大小便三项、会阴、两条腿、腿没劲、无力加重）不能放进 traps，否则模拟患者会答"不清楚"，触发 `rf_uncertain_red_flag`。所以这类事实被挂错，只能从误报和多余提醒里看到，不计入 X2。
6. 样本量：48 条阳性要认出 44 条才过 80% 下限；每类 8 条只能描述；21 条反例 0 误报时，上限仍有 15.5%。
7. 延迟是在开发机上测的，演示机要另测。
