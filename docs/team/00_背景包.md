## 2. 产品现状：体迹 AI
**一句话**：帮小型专科门诊（康复 / 疼痛 / 骨科 / 全科）把患者在见医生前、和两次就诊之间说的话，变成可核对的信息和有人负责的事项。首个场景：成年腰背痛；膝痛做了工程复用示范。

**已经能跑的**（FastAPI + React，本机 http://localhost:8000 与 http://localhost:5173 正在运行）：
- 患者端（手机网页）：开始页适用范围确认（≥18 岁、未怀孕）→ 2D 身体图标记疼痛与放射 → 用自己的话描述 → 模型把口语抽成协议定义的事实（带原话引用）→ **一键核对**（关键信息请患者逐条点对/不对/不确定）→ 协议补问（红旗先问）→ 确认页。
- 紧急红旗（大小便变化、会阴麻等）触发后立即提示并**终止问询**，主按钮是打电话给门诊 / 120。
- 医生端：按紧急程度排序的列表；**接诊速览**（紧急程度、一句话主诉、面诊要当面确认的三件事）；摘要每条事实都能点回原话；六种事实状态（有 / 明确否认 / 未问 / 问了没答 / 不确定 / 矛盾）；**病历初稿**（确定性拼接，不调模型，逐段注明出处）；任务看板（系统只能创建任务，"已完成"必须有人点）；随访变化卡（相比上次变了什么）；给患者的随访说明（默认按医生审定的术语对照表整理，不调模型）；打印导出。
- 九项自动验收检查（出处、不补全、引文逐字、越界、矛盾、红旗、通知状态、版本、确认顺序）；54 项后端测试。
- 模型层：离线词表（mock，默认）/ Claude / OpenAI 兼容接口（国产模型或本地模型）；任何模型异常都退回离线词表并在界面标出。

**七条核心原则**：未问≠没有；每条事实可回溯原话；矛盾不自动取其一；模型不决定流程（问什么、何时升级由医生写的协议决定）；修改留版本；任务由人推进；发送≠看到≠理解。

## 4. 已知的硬伤与争议
1. **痛点证据为零**：没有一家门诊的原话或数字。巨头已覆盖：蚂蚁「智慧医疗 AI 一体化方案」（400 余家等级医院，含诊前咨询、诊后复访，有云端与本地化部署）；讯飞智医助理（7.7 万家基层机构）；诊所 SaaS（ABC 诊所管家 2,599–26,800 元/年，已含 AI 病历、AI 辅助诊疗、随访，但**没有诊前患者端**）。"免费的够不够用、小门诊为什么付钱"没有答案。
2. **"AI 的肌肉"不够**：默认演示是关键词词表；真实模型从未评测。
3. **题太多**：平均 14.4 题 + 身体图 + 描述；普通人可能填不完。
4. **定价是假设**：插件按活跃随访患者每月 10–20 元，或独立订阅每月 300–1,000 元；深圳试验田上限约 350 万元/年。
5. **单一专科**、**医生端无登录**、**商务角色空缺**。
6. 医学内容（协议、红旗、术语）全是 AI 草案。

## 5. 约束
- **诚实**：模拟的东西必须标"模拟"；不得编造访谈、用户、付费、临床结果；数字要有出处。
- **边界**：不诊断、不处方、不给用药建议；红旗是协议写好的固定提示，不是模型判断；真实患者数据只走境内或本地模型。
- **资源**：1 名工程（大脑，能力强、写得快）；医生队友目前不可用（先由 AI 模拟临床视角）；现金 4.8 万元；本机 M2 Pro 32GB + Ollama。
- **可以推翻重来**：如果现在解决的问题不对、设计不好，直接说，给出替代方案和理由。
