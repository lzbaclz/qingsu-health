# 02 · 系统架构（0.3.1）

React/Vite 患者与医护页面通过同源 API 连接 FastAPI。SQLModel/SQLite 保存原话、事实版本、协议快照、计划版本、事件核实、任务、通知与审计。独立 lifespan worker 定期扫描任务，前端定时更新看板。

## 模型与程序的分工

模型抽取协议字段和主体/时间候选、生成受约束叙述，并比较计划原文与患者复述。程序检查字段、值和逐字引文，再决定事实状态。引文合法只能证明出处存在，不能证明语义正确。

问询与提醒由协议及确定性表达式决定。处置差异追问在同协议下枚举事件候选解释，比较提醒等级、责任角色和停止问询条件。安全必问保留。矛盾候选可能触发待核实提醒，事实仍保持矛盾。

复述比较使用独立结构化 schema。结果限于一致/相反/遗漏/不清楚及引文，不输出新医疗建议。真实模型失败时保留回复并交人工；mock 只做字面展示。医护确认不会自动把执行状态改为完成。

## 核心模块

| 模块 | 位置 |
|---|---|
| 身份、会话与机构隔离 | backend/app/security.py、api/auth.py |
| 固定协议快照 | protocol/loader.py、ProtocolSnapshot |
| 事件候选与处置差异 | events/service.py、protocol/triage.py |
| 问询及断点恢复 | questioning/engine.py、services/encounter.py |
| 固定计划与复述 | course/teachback.py |
| 生活目标与比较 | course/goals.py |
| 候选预演 | protocol/preview.py |
| 任务调度与可选 webhook | course/worker.py |
| 数据维护 | data_admin.py |

每个就诊绑定内容哈希，随访继承该快照。新文件不修改旧记录的执行规则。新特性在旧协议 schema 默认关闭。

## 运行与可观察性

mock/ollama/compat/anthropic 提供者分开标识。本次真实推理选本机 qwen3:4b，仅输入合成文本。症状抽取可配置失败退回词表并标注；评测强制禁用兜底，避免混淆模型。

公共 `/api/health` 只返回存活信号。完整运行状态在需医护登录的 `/api/status`，模型自检也需授权。生产模式隐藏 API 文档与演示接口。当前列迁移工具只适合原型，正式部署需要经演练的数据库迁移与运维方案。
