# 03 · 数据模型与事实状态（0.3.1）

`Patient` 存机构内假名编号。原始身份映射由机构控制；假名编号仍可能关联健康数据，不宣称匿名化。

`Encounter` 绑定患者、机构、协议哈希、原就诊和原计划版本。`Entry` 保留不可变原话与问答，`Fact` 保存六态与版本链：present、denied、not_asked、asked_unanswered、uncertain、conflicting。未问和不知道不转为否认。

`SymptomEvent` 保存原话、主体、时间关系、逐字时间线索、报告时间、模型候选与核实历史。historical 是过去提及且现在不明；past 必须表示现在已结束。后来的原话不被旧事件回答覆盖。医生改主体/时间的记录不静默撤销已有红旗。

`PlanVersion` 保存每版说明、选取的原文要点、内容哈希、发布身份与时间。当前版本指针、通知和任务一起发布，过期提交不能覆盖新版本。`TeachbackResponse` 按计划版本和提交标识幂等保存原话、模型差异、执行状态、障碍和医护复核历史。

`FunctionalGoal` 是患者确认的固定活动、单位与条件；`FunctionalObservation` 追加观察日期、状态、值、实际条件和原话。不测量时 value=null。改变目标需新建，不能把两个不同目标直接比较。

`Task` 保留状态、责任、截止与联系记录。未接通不等于完成。`Notification` 的 sent 指站内提供，acknowledged 指点击确认收到，不代表理解。`TaskDelivery` 单独保存外部投递尝试，未配置时明确无送达。

`StaffAccount`、`AccessSession`、`PatientInvite` 管理账号、会话和单次邀请。口令采用 scrypt；令牌仅存摘要。患者和医护请求均校验机构/对象归属。`AuditLog` 身份来自服务器。

按患者导出排除认证令牌摘要；删除默认预览并需指定机构和对象，备份/恢复只写新文件。边界和操作见 docs/23。
