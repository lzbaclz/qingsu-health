# 01 · 产品框架

## 1. 一句话定义
**体迹 AI：帮小型专科门诊把患者在见医生前、和两次就诊之间说的话，变成可核对的信息和有人负责的事项。**
（技术描述：面向专科门诊的 AI 症状表达与病程协作工具。）
患者通过身体地图和自然语言在就诊前把症状说清楚；系统进行有针对性的补充问询，生成有原始证据的就诊摘要供医生核对；就诊后继续记录变化，并追踪需要人工处理的事项。

## 2. 服务谁、卖给谁
| 角色 | 定义 | 在产品里做什么 |
|---|---|---|
| 患者 | 已由门诊邀请使用（就诊前）或已经医生评估并纳入随访（诊后）的成年人 | 标记身体图、用自己的话描述、回答限定问题、**确认记录是否准确**、看到并确认医嘱 |
| 医生 | 门诊执业医生 | 核对摘要（每条能点回原话）、修正并留版本、确认、设置随访计划 |
| 医护/工作人员 | 获授权的护士或助理 | 推进任务（查看→联系→处理→完成）、处理红旗与随访提醒 |
| **购买者** | 小型持证康复/全科/疼痛门诊负责人 | 为"信息更完整、整理更省时、异常有人接手"付费 |

首个示范场景：成年腰背痛。**这是工程占位选择，最终专科以临床队友的能力与可获得的机构合作为准。**

## 3. 首版范围与明确不做
| 做 | 不做（首版） |
|---|---|
| 就诊前采集：身体图 + 自由描述 + 协议限定补问 + 患者确认 | 全科自动诊断、疾病名称输出 |
| 医生端可回溯摘要：事实/证据/缺口/矛盾/红旗，修正留版本 | 自动处方、剂量调整、用药建议（用药只记录患者自述） |
| 诊后随访：变化卡（相比上次变了什么）、医嘱送达状态、任务追踪 | 个性化训练动作自动生成、影像诊断 |
| 协议驱动的红旗：立即展示经审核的提示 + 生成任务 | 可穿戴、自研硬件、3D 个体重建 |
| 验收检查：系统自证九项约束 | 声称"临床准确率""改善疗效" |

## 4. 两条主流程
### 4.1 就诊前采集（pre_visit）
```
开始页（用途/边界/紧急提示/适用范围逐条确认：年满 18 岁、没有怀孕，选"不对"不进入/知情勾选）
 → 身体图（标准 2D 前/后视图；主要位置 + 放射位置）
 → 自由描述（原话保存；模型抽取候选事实，程序校验引文）
 → 一键核对（原话里抽到的关键信息逐条"对 / 不对 / 不确定"；不对的会被重新直接问）
 → 协议补问（一次一题；允许"不清楚/跳过"；矛盾先澄清）
 → 若触发紧急红旗：立即显示经审核的提示并**终止问询**，患者端只剩"打电话给门诊 / 拨打 120"与"把已填写的内容交给医生"
 → 患者确认（确认"记录是否准确"，可修改；矛盾未澄清不能确认）
 → 医生端：摘要 v1 + 验收报告 + 待核对任务
 → 医生核对/修正（新版本）→ 确认 → 设置随访计划（医生撰写给患者的话）
```
### 4.2 诊后随访（follow_up）
```
患者收到医嘱通知（sent）→ 打开（seen）→ 确认理解（acknowledged）
 → 随访入口（关联上次就诊）→ 身体图重标 + "相比上次"问题
 → 医生端变化卡：changed / new / unconfirmed / unchanged + 触发的红旗 + 医嘱送达状态
```
随访**不继承**上次的事实值——每次从"未问"开始，只在变化卡里对比，避免旧结论掩盖变化。

## 5. 患者端页面
| 路由 | 页面 | 关键设计 |
|---|---|---|
| /p | 开始 | service_notice、emergency_notice（全程可见）、服务时间、适用范围确认（scope.eligibility）、知情勾选、患者编号 |
| /p/e/:id/body | 身体图 | 前/后切换、主要/放射两种标记、左右以患者自身为准 |
| /p/e/:id/describe | 自由描述 | 原话完整保存；不要求医学术语 |
| /p/e/:id/questions | 补问 | 一次一题；yes_no/单选/多选/量表/文本/身体区域/澄清/一键核对；不清楚/跳过 |
| /p/e/:id/urgent | 紧急终止 | "请现在就联系医生"；门诊电话与急救电话主按钮；不再答题 |
| /p/e/:id/confirm | 确认 | 已明确 / 表达不确定 / 未回答 / 矛盾；可修改；确认的是记录不是诊断 |
| /p/e/:id/done | 完成 | 下一步与服务时间；医嘱通知的"已看到/已理解" |
| 全局 | 紧急横幅 | 协议批准的红旗提示，不可关闭 |

## 6. 医生端页面
| 路由 | 页面 | 关键设计 |
|---|---|---|
| /d | 就诊列表 | **按紧急程度排序**：紧急 → 当天联系（含患者核对时否认的紧急红旗）→ 常规 → 未触发红旗，同级里等医生核对的在前；未完成任务、矛盾数 |
| /d/e/:id | 详情 | 最上面是**接诊速览**：紧急程度、一句话主诉、红旗、面诊时要当面确认的三件事（从矛盾、表达不确定、关键事实未明确里按优先级挑）；然后是变化卡（随访）/ 摘要 / **病历初稿**（只用患者确认过的事实拼成主诉、现病史、阴性、未明确，医生核对后复制）/ 医生操作 / 任务；事实与证据、验收检查、版本、问答记录**默认收起**；原始记录在侧栏 |
| /d/tasks | 任务看板 | 未查看→已查看→已联系→待处理→已完成；完成必须有人 |
| /d/protocols | 协议 | 版本、状态、待审条目（review_gaps） |
| /d/e/:id/print | 打印 / 导出 | 一页 A4 摘要，浏览器"存储为 PDF"；门诊存档或纸质交接 |
| 顶栏 | 模型标识 | 显示抽取用的是真实模型还是离线词表（含失败兜底） |

## 7. 不可妥协的原则
1. **未问 ≠ 没有**：六种事实状态；摘要把"未知"单独列出。
2. **每条事实可回溯**：证据引用逐字来自原始记录。
3. **矛盾不自动取其一**：先澄清；澄清不了标"不确定"，并呈现给医生。
4. **模型不决定流程**：问什么、何时升级、给患者看什么，由协议决定；模型只抽取与叙述。
5. **修改留版本**：事实、摘要、任务全部有版本与审计。
6. **任务由人推进**：系统只能创建；"已处理"必须有人。
7. **发送 ≠ 看到 ≠ 理解 ≠ 执行**：分开记录，分开展示。
8. **漏抽由问卷兜住，错抽由核对兜住**：原话里抽到的关键信息先请患者核对，不对的重新直接问。
9. **紧急时不再让患者答题**：紧急红旗触发后终止问询，主按钮是"现在就联系"。
10. **AI 帮医生定位"先看谁、该问什么"，不定位"是什么病"**：紧急排序、接诊速览、病历初稿都是按协议对事实的确定性整理；给患者的说明由医生决定并发送，AI 只把医生要点改写成通俗说法，改写里冒出要点里没有的药名、病名、剂量会提醒医生删除。

## 8. 需要验证的差异化（不是已拥有的优势）
| 主张 | 怎么量 |
|---|---|
| 接入更轻 | 第二家机构上线工时；新增一个协议的临床/工程工时 |
| 信息更可核对 | 独立医生检查摘要与原始证据：关键事实完整率、编造率、"未问写成否认"率 |
| 净工作量更低 | 医生阅读 + 纠错 + 联系患者 + 误报处理的总时间，与"表单 + 人工整理"对照 |

## 9. 已实现 / 未实现（诚实清单，BP 必须照此表述）
- 已实现：上述全部流程的可运行原型（后端 + 前端，含开始页适用范围确认、一键核对、紧急终止、接诊速览与紧急排序、病历初稿、给患者说明的改写、打印导出、可用性测试埋点与植入错抽）、协议机制、验收检查、评测运行器（三层口径）、80 个场景 + 20 句口语压力集、三种模型适配（离线词表 / Claude / 国产兼容接口）与"任何异常都退回离线词表"、医生审核决定 → 协议 v0.2 候选的生成工具。
- 用模拟数据验证过：54 项后端测试；80 场景与压力集的离线词表基线；同一位如实作答的模拟患者下读原话与只发问卷的对照；浏览器走通正常、矛盾、紧急终止、随访四条路径与医生端速览、病历初稿（含被否认红旗的"需核实"）、说明整理。
- 未实现 / 未验证：真实模型评测（没有 key，从未跑过）、医生审核（0 条决定）、门诊访谈（0 家）、10 人测试（0 人）、医生端登录、真实患者数据。
- 依赖外部：机构合作、伦理/合规判断、第二位临床复核者。
