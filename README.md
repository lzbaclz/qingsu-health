# 体迹 AI（TiJi AI）

面向持证肌骨康复门诊的疗程变化核实助手。首个模拟场景为成人腰背痛。患者描述近况，系统保留主体、发生时间、报告时间与原话，按协议比较不同解释是否会改变处理，再交医护核实。

当前应用版本 **0.3.1**，默认协议 `lbp_adult_v0.2` 内容版本 **0.2.5**。协议仍是 AI 模拟草案，生产模式拒绝使用。当前只完成工程和模拟验证，尚无真实临床批准、用户收益或付费证明。

## 启动

```bash
make setup
make demo       # 独立模拟数据库；不会清空已有数据库
make frontend   # 另开终端，http://localhost:5173
```

账号 `demo-doctor` 的随机口令保存在 `backend/.local/demo-v031-access.txt`（权限 0600）。`make demo` 使用本版独立演示库 `backend/.local/demo-v031.db`；旧演示库保留。进入医生端后生成一次性患者邀请。需要全新演示数据时，使用 `python -m app.demo --database 新路径 --access-file 新路径`，避免覆盖已有记录。每条记录沿用创建时的协议快照，旧记录不会自动升级为新协议。

## 已接入的功能

| 功能 | 当前行为与边界 |
|---|---|
| 原话与病程事件 | 保留说的是谁、何时发生、何时报告。过去起病不等于已经结束，首次记录不等于新发。支持患者修正和医生复核历史 |
| 处理差异驱动核实 | 确定性比较同一协议下候选解释的提醒与责任分支。保留安全必问；当前是实验策略，尚未证明总体少问或更准确 |
| 计划复述 | 每版说明有固定要点、哈希和回复。模型仅比较表达，医护核实；执行障碍独立记录。离线模式只作字面匹配，模型不可用时交人工 |
| 生活功能目标 | 患者确认自己的日常目标与固定条件。观察按原始日期追加，条件不同或缺测不算改善，不作疗效预测 |
| 协议影响预演 | 候选在内存环境比较下一问、红旗与责任。不会覆盖运行协议，不代表完整路径或临床正确性 |
| 身份与交接 | 医护登录、角色与机构隔离；患者一次性邀请和到期会话；联系失败仍有后续任务 |
| 调度与数据维护 | 独立 worker、失访规则、发送状态；本机备份、恢复、按患者导出与受控删除工具 |

## 验证

```bash
make test
(cd frontend && pnpm run build && pnpm run lint)
backend/.venv/bin/python eval/context_benchmark.py --provider mock
backend/.venv/bin/python eval/context_benchmark.py --provider ollama --model qwen3:4b
backend/.venv/bin/python eval/runner.py --split dev --protocol lbp_adult_v0.2 --patient truthful
```

本次后端 **217 项测试通过**。最新评测原始结果在 `docs/release_20260927/eval/`，包括失败、计划分母、代码/数据/协议哈希、真实推理时间。旧报告仅作历史记录；不能把旧版 80/80 或单元测试通过率当作当前临床准确率。72 条封存留出集未查看、未运行。

模型选项：`mock` 离线词表、`ollama` 本机模型、`compat` 兼容接口、`anthropic`。本轮真实推理使用本机模型和合成语句。未经数据处理授权，不把真实患者信息发送给外部服务。

外部通知默认未配置。`queued` 是待取回，`sent` 是提供到患者页面，`seen` 和 `acknowledged` 是患者点击事件，均不等于理解、执行或实际联系成功。
